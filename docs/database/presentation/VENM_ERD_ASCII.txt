+-------------------+--------------------+-------------------+--------------------+--------------+-------------------+-----------------------+
| PARENT ENTITY     | PARENT PK          | CHILD ENTITY      | CHILD FK           | CARDINALITY  | ENFORCEMENT LEVEL | REFERENTIAL ACTION    |
+-------------------+--------------------+-------------------+--------------------+--------------+-------------------+-----------------------+
| Collection        | id (UUID)          | Product           | collectionId       | 1 : N (0..N) | Database Engine   | ON DELETE SET NULL    |

| User              | id (UUID)          | Inquiry           | userId             | 1 : N (0..N) | Application Code  | Nullable (Guest Mode) |
| Product           | id (UUID/Code)     | Inquiry           | productId          | 1 : N (0..N) | Application Code  | Point-in-time Snapshot|
| User              | id (UUID)          | ActivityLog       | adminUserId        | 1 : N (0..N) | Application Code  | Polymorphic Actor     |
| Product           | id (UUID/Code)     | Setting           | data.assignedIds   | N : M        | Application Code  | JSON Array in Setting |
| Product           | images (JSON)      | Media             | url                | N : M        | Application Code  | String Path Matching  |
+-------------------+--------------------+-------------------+--------------------+--------------+-------------------+-----------------------+

Legend for Cardinality Notation:
  1 : N (0..N) => Parent entity may have zero, one, or many child records.
                  Child record must have zero or one parent record (Optional relationship).

SECTION 5: STANDARD NOTATION LEGEND FOR YOUR PROFESSOR
========================================================================================================================

1. KEY MARKINGS:
   PK = Primary Key (Guarantees entity integrity; unique, non-null surrogate identifier)
   FK = Foreign Key (Referential integrity pointer connecting child table to parent table)
   UK = Unique Key Constraint (Guarantees attribute uniqueness across all table rows)

2. CARDINALITY CROW'S-FOOT SYMBOLS:
   +---------+--------------------+-----------------------------------------------------+
   | SYMBOL  | MEANING            | EXAMPLE IN VENM DATABASE                            |
   +---------+--------------------+-----------------------------------------------------+
   |  ||     | Exactly One (1)    | A Product references exactly one Category (or null) |
   |  o|     | Zero or One (0..1) | An Inquiry may belong to 0 or 1 registered Users    |
   |  |{     | One or More (1..N) | A Collection must have at least one Product         |
   |  o{     | Zero or More (0..N)| A Collection may have zero, one, or many Products   |
   +---------+--------------------+-----------------------------------------------------+

3. LINE STYLES:
   SOLID LINE  (───────) = Database-Enforced Foreign Key (PostgreSQL RDBMS constraint)
   DASHED LINE ( - - - ) = Application-Managed Soft Link (Express Controller business logic)
